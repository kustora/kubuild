`@kubuild/html-import` compiles static HTML (a string, an `.html` file, or a `.zip` with HTML, CSS and assets) into a regular, validated `PageDocument`. The result is a normal KUBUILD page: it opens in the editor, renders with `@kubuild/renderer`, and exports as `.stora` like any page built from scratch.

The importer is a **compiler, not a browser**. It never runs scripts and never touches the DOM; it parses HTML with `parse5`, resolves the CSS cascade statically, and maps each element to a built-in component. It runs the same way in Node, in a worker, and in the browser. Pages styled with Tailwind utility classes from the Play CDN are [mapped without running Tailwind](#tailwind-utility-classes), and the editor can optionally [measure styles in an inert browser frame](#browser-snapshot-styles) instead of using the static cascade.

<Callout type="warn" title="HTML is untrusted input">
  Treat every imported page like an imported `.stora` package: it may come from anyone. The importer strips scripts, event handlers and unsafe URLs, and the final document must pass `PageDocumentSchema` and `validateDocumentSecurity` before it is returned. Still run imports where a failure cannot hurt (a worker or a server job with limits), and keep your own [security checklist](/docs/integration/security) in place.
</Callout>

## Installation

```bash
pnpm add @kubuild/html-import
```

`@kubuild/react` re-exports the four entry points and the result/option types (`importHtml`, `importHtmlZip`, `htmlToNodes`, `importHtmlToStoraPackage`, `HtmlImportOptions`, …). Import from `@kubuild/html-import` directly when you write [custom rules](#custom-mapping-rules), because the rule helpers (`buildResponsiveStyles`, `getAttribute`, `HTML_IMPORT_DIAGNOSTIC_CODES`, …) are only exported there.

## The Pipeline

Every entry point runs the same steps:

| Step | What happens |
| :--- | :--- |
| 1. **Parse** | `parse5` builds an AST. Input over `limits.maxDocumentSizeBytes` (default 5 MB) is rejected with `LIMIT_EXCEEDED`. Full documents (`<!doctype>`, `<html>`, `<head>` or `<body>`) and fragments are both accepted. |
| 2. **Sanitize** | Allowlist-based AST sanitizer: drops dangerous elements, `on*` handlers, `srcdoc`, `formaction`, unsafe URLs and dangerous inline styles. |
| 3. **Cascade** | Collects `<style>`, `<link rel="stylesheet">` and `options.stylesheets` in source order, appends the rules for [Tailwind utility classes](#tailwind-utility-classes) when Tailwind is detected, then resolves specificity, `!important`, inline styles, custom properties and inheritance per element. `@media` rules become breakpoint overrides and `:hover`-style rules become `states`. An optional [`styleOverride`](#overriding-computed-styles) hook can replace the result per element. |
| 4. **Map** | The rule registry turns each element into a node (`heading`, `image`, `flex`, …). Elements no rule handles become sanitized `html-embed` nodes (or are dropped). |
| 5. **Normalize** | Removes style values that equal what the node already inherits, collapses unstyled single-child wrappers, merges adjacent text with identical styles, flattens branches deeper than `limits.maxTreeDepth`, and assigns deterministic IDs (`root-page`, `node-1`, `node-1-2`, …). |
| 6. **Assets** | Resolves relative URLs against `baseUrl`, blocks executable files, calls `assetResolver` for images, videos and fonts, and collects web fonts into `theme.fonts`. |
| 7. **Validate** | Assembles the `PageDocument` and checks it against `PageDocumentSchema` and `validateDocumentSecurity`. A document that fails is never returned. |

## API

| Function | Input | Returns |
| :--- | :--- | :--- |
| `importHtml(html, options?)` | HTML document or fragment string | `Promise<HtmlImportResult>`: `{ success, document?, report, error? }` |
| `htmlToNodes(html, options?)` | HTML string | `Promise<HtmlNodesResult>`: `{ success, nodes, report, error? }`, the converted nodes without a `page` root, for inserting into an existing document |
| `importHtmlZip(archive, options?)` | `Uint8Array` or `ArrayBuffer` of a `.zip` | `Promise<ZipImportResult>`: the `importHtml` result plus `entryHtmlPath` and `archiveAssets` |
| `importHtmlToStoraPackage(html, options?)` | HTML string | `Promise<HtmlStoraPackageResult>`: `{ success, packageBuffer?, document?, report, error? }` |

None of these functions throw. Malformed input, limit violations, failing resolvers and invalid output all come back as `success: false` with an `error` message and the diagnostics collected so far in `report`.

`importHtml` builds the page root from `<body>`: body styles become the `page` node's styles (on top of `minHeight: 100vh` and a white background), and when `<body>` holds nothing but a single `<main>`, that `<main>` is merged into the root instead of becoming an extra section. The document title comes from `metadata.title`, then `<title>`, then `"Untitled Page"`. The description comes from `metadata.description`, then `<meta name="description">`.

## Options

`HtmlImportOptions` is accepted by all four functions (`ZipImportOptions` and `HtmlStoraPackageOptions` extend it):

| Option | Type | Purpose |
| :--- | :--- | :--- |
| `baseUrl` | `string` | Resolves relative stylesheet hrefs, `src`, `srcset`, `poster` and CSS `url(...)` values. |
| `stylesheets` | `string[]` | Extra CSS applied **after** the page's own sheets. Each entry is either raw CSS or a stylesheet URL (fetched through `fetchStylesheet`). |
| `fetchStylesheet` | `(url) => string \| null \| Promise<…>` | The only way external CSS is read. Without it, `<link rel="stylesheet">` is reported as `ASSET_UNRESOLVED` and skipped. Return `null` to skip a sheet. |
| `assetResolver` | `({ url, type }) => string \| AssetReference \| null \| Promise<…>` | Rehosts media. `type` is `'image' \| 'video' \| 'font' \| 'other'`. Return a URL or an `AssetReference` to replace the value, or `null` to keep the resolved URL (reported as `ASSET_UNRESOLVED`, severity `info`). |
| `rules` | `HtmlMappingRule[]` | Host mapping rules, merged over the defaults. See [Custom Mapping Rules](#custom-mapping-rules). |
| `allowedComponentTypes` | `string[] \| Set<string>` | Custom component types rules may emit. Any other non-built-in type is dropped. |
| `limits` | `Partial<DocumentSecurityLimits>` | `maxDocumentSizeBytes` (default 5 MB here), `maxNodeCount` (default **1000** here), `maxTreeDepth` (32), `allowedUrlSchemes`, `prohibitedAssetExtensions`, `maxZipExpansionRatio`, and the other core limits used by the final security check. |
| `metadata` | `Partial<DocumentMetadata>` | Overrides the generated document metadata (`title`, `description`, `author`, `tags`, …). |
| `theme` | `Partial<Theme>` | Initial theme tokens. Fonts found in the page are merged into `theme.fonts`. |
| `fallback` | `'embed' \| 'drop'` | What to do with elements no rule matches. `'embed'` (default) keeps them as sanitized `html-embed` nodes; `'drop'` removes them. |
| `preserveButtonLinks` | `boolean` | Keep button-styled `<a>` elements as `link` nodes instead of converting them to `button`. |
| `tailwind` | `'auto' \| true \| false` | [Tailwind utility class](#tailwind-utility-classes) mapping. `'auto'` (default) maps classes when Tailwind is detected; `true` always maps, `false` never does. |
| `styleOverride` | `(element, computed) => ComputedElementStyles \| null \| undefined` | Replaces the statically computed styles of an element. See [Overriding Computed Styles](#overriding-computed-styles). |

## Element Mapping

Default rules, by HTML element:

| HTML | Component | Notes |
| :--- | :--- | :--- |
| `section`, `header`, `footer`, `main`, `nav`, `article`, `aside` | `section` | Keeps `id`, `role`, `aria-label`. |
| `div`, `address` | `flex` / `grid` / `container` | Chosen from the computed `display`. |
| `h1`–`h6` | `heading` | `level` 1–6, `text`. |
| `p` | `paragraph` | `text`. |
| `span`, `strong`, `b`, `em`, `i`, `small`, `mark`, `u`, `s`, `del`, `ins`, `sub`, `sup`, `abbr`, `cite`, `q`, `time` | `text` | `as` is set to the tag, so bold/italic/sub/sup semantics survive. An element without text (a decorative `<span class="dot">`) becomes a styled `container`. |
| `blockquote` | `blockquote` | `text` and `cite` (from the attribute or a child `<cite>`). |
| `pre`, `code` | `code-block` | Whitespace is preserved; `language` comes from a `language-*` / `lang-*` class. |
| `hr` | `divider` | |
| `a` | `link` | `href` (unsafe schemes become `#`), `target`, `rel`. Text-only links get `text`; links with element children keep them as children. |
| `a` with `role="button"`, a `btn`/`button` class, or a background color **and** padding | `button` | `label`, `href`. Disabled with `preserveButtonLinks: true`. |
| `img`, `picture` | `image` | `src` (best `srcset` candidate for `<picture>`), `alt`, `loading`, `width`, `height`. |
| `video` | `video` | `src` (or the first `<source>`), `controls`, `autoplay`, `loop`, `muted`, `poster`. |
| `iframe` with a YouTube or Vimeo `src` | `video` | Other iframes fall back to `html-embed`. |
| `svg` | `icon` | The sanitized SVG markup in `svg`. |
| `form` | `form` | `method`, `action`. An `action` is reported (`URL_BLOCKED`, severity `info`) because the host must wire submission itself; see [Forms & Actions](/docs/guides/forms-and-actions). |
| `input` | `input`, `checkbox`, `radio`, `button`, `button-submit` | By `type`. |
| `textarea`, `select` | `textarea`, `select` | `select` gets its `options` from `<option>` children. |
| `button` | `button` / `button-submit` | `type="submit"` gives `button-submit`. Icon-only buttons (just an `<svg>`/`<img>`) become `html-embed` so the icon survives; a button with no text and no icon uses its `aria-label` as the label. |
| `label` | `checkbox` / `radio` / `text` | A label wrapping a checkbox or radio is merged into that control. |
| `ul`, `ol` / `li` | `list` (`ordered`) / `list-item` | A text-only `li` uses `text`; mixed content stays in children only. |
| `table`, `tr`, `td`/`th` | `table`, `table-row`, `table-cell` | `thead`/`tbody`/`tfoot` rows are flattened; `colSpan`/`rowSpan` are kept. |
| Anything else (`canvas`, `details`, other iframes, …) | `html-embed` | Sanitized markup, reported as `ELEMENT_FALLBACK_EMBED`. With `fallback: 'drop'` the element is removed instead (`ELEMENT_DROPPED`). |

Loose text directly inside a block (for example text next to an `<a>` inside a `<div>`) becomes a `text` node that carries only the inherited text properties of its parent. Whitespace-only text between elements is removed, and it is never kept inside flex or grid parents, where CSS would not render it either.

## CSS Support

The cascade is resolved per element, using the same precedence as a browser:

1. `!important` beats normal declarations; inline `!important` beats stylesheet `!important`.
2. Inline `style="…"` beats stylesheet rules.
3. Higher specificity wins; later source order breaks ties.

Selectors are matched with `css-select`, so type, class, ID, attribute, descendant/child/sibling combinators, `:not()`, `:first-child`, `:nth-child()` and similar structural pseudo-classes all work. Property names are converted to camelCase (`font-size` → `fontSize`) and stored as-is in the portable style object.

### Inheritance and custom properties

- **Inherited text properties** (`color`, `fontSize`, `fontFamily`, `fontWeight`, `fontStyle`, `lineHeight`, `textAlign`, `letterSpacing`) flow from parent to child. The normalizer then removes every value a node would inherit anyway, so styles are written once, on the ancestor that sets them.
- **Custom properties** (`--brand: #2563eb`) cascade like other properties: tokens on `:root`, on any matching rule, or inline are resolved into `var(--brand, fallback)` usages. A `@media` rule that only changes a token re-resolves the declarations that use it, so the change appears as a breakpoint override.

### Media queries → breakpoints

KUBUILD breakpoints are `desktop` (≥ 1024px), `tablet` (768–1023px) and `mobile` (< 768px), and their layers are **disjoint**: `mobile` does not inherit from `tablet` (see [Responsive Cascade](/docs/guides/responsive-cascade)). CSS width queries cover ranges instead, so a query is applied to **every breakpoint whose width range it covers by more than half**. Override layers only store values that differ from `base`, and later queries still override earlier ones per breakpoint.

| Query | Breakpoints | Diagnostic |
| :--- | :--- | :--- |
| `(max-width: 767px)` | `mobile` | — |
| `(max-width: 1023px)` | `tablet`, `mobile` | — |
| `(max-width: 991px)` | `tablet`, `mobile` | `CSS_MEDIA_APPROXIMATED` |
| `(min-width: 768px)` (mobile-first) | `tablet`, `desktop` | — |
| `(min-width: 768px) and (max-width: 1023px)` | `tablet` | — |
| `(min-width: 1280px)` | `desktop` | `CSS_MEDIA_APPROXIMATED` |
| `(max-width: 480px)` | `mobile` | `CSS_MEDIA_APPROXIMATED` |
| `print`, `(prefers-color-scheme: dark)`, other non-width queries | ignored | — |

`min-width`/`max-width` in `px`, `rem` and `em` (16px base) and range syntax (`width < 600px`) are understood. A query whose bounds don't sit on a KUBUILD breakpoint edge is reported once per query as `CSS_MEDIA_APPROXIMATED`.

### Pseudo-classes → states

Rules ending in `:hover`, `:focus`, `:active`, `:focus-visible`, `:disabled` or `[disabled]` are written to `styles.states` (`hover`, `focus`, `active`, `focusVisible`, `disabled`) as deltas against the base style. Other interactive pseudo-classes such as `:visited` are ignored.

### Not supported

| Feature | What happens |
| :--- | :--- |
| `@import` | Dropped, reported as `CSS_UNSUPPORTED_PROPERTY`. Pass the imported sheet through `stylesheets` instead. |
| Pseudo-elements (`::before`, `::after`, `::placeholder`, …) and `:has()` | The selector is skipped, reported once per selector as `CSS_UNSUPPORTED_SELECTOR`. |
| `@keyframes` animations | Not converted to KUBUILD animations. |
| `@supports`, `@container`, `@layer` | Their conditions are not evaluated: the rules inside apply as if they were top-level. |
| Dangerous values (`expression()`, `javascript:`/`vbscript:` URLs, `behavior`, `-moz-binding`, …) | The declaration is dropped (`URL_BLOCKED` or `CSS_UNSUPPORTED_PROPERTY`). |
| Tailwind utility classes | A common subset is [mapped by the importer](#tailwind-utility-classes). For exact fidelity, compile the CSS and pass it through `stylesheets`. |

## Tailwind Utility Classes

Many AI-generated landing pages load Tailwind from the Play CDN and have no stylesheet at all: the CSS is generated at runtime by a script that the sanitizer removes. The importer therefore ships its own mapper (`tailwind.ts`) that turns the common subset of **Tailwind v3** utilities (default theme scale) into ordinary CSS class rules. Those rules go through the normal cascade, so the document only ever stores plain style values per breakpoint and state; no class names, `--tw-*` variables or Tailwind runtime end up in it.

<include meta='title="tailwind.ts"'>../../../examples/html-import/tailwind.ts</include>

For this input the `section` becomes a column `flex` with `gap: 1rem` and `flexDirection: row` on `tablet` and `desktop`, the heading gets `fontSize: 2.25rem` with a `3rem` override, `bg-brand` resolves through the inline config to `#10b981`, `hover:bg-emerald-700` lands in `styles.states.hover`, and `ring-2` is reported.

### Detection

`options.tailwind` controls when classes are mapped:

| Value | Behavior |
| :--- | :--- |
| `'auto'` (default) | Map when the page has a Tailwind Play CDN or `@tailwindcss/browser` script, an inline `tailwind.config = …` script, or a `<style type="text/tailwindcss">`, **or** when at least 5 distinct classes carry a clear Tailwind signature (`md:`/`hover:`-style variants, palette shades such as `bg-gray-50`). Bootstrap, Webflow and plain-CSS pages do not trigger it. |
| `true` | Always map. |
| `false` | Never map. |

Detection runs on the raw HTML, before the sanitizer removes the scripts. Classes that the page's own CSS or `options.stylesheets` already define are left to that CSS, so passing a compiled Tailwind stylesheet still takes precedence and nothing is mapped twice.

<Callout type="info" title="tailwind.config is never executed">
  An inline `tailwind.config` is read **statically**, and only when it is a plain object literal (strings, numbers, booleans, objects, arrays). Functions, spreads, references, calls or `__proto__` keys make the whole config unsupported (`CSS_UNSUPPORTED_PROPERTY`, warning). Only `theme.colors`, `theme.fontFamily` and their `theme.extend` counterparts are applied; other keys such as `spacing` are reported (`CSS_UNSUPPORTED_PROPERTY`, info) and the default scale is used.
</Callout>

### Variants

- **Responsive prefixes** become `min-width` queries (`sm` 640px, `md` 768px, `lg` 1024px, `xl` 1280px, `2xl` 1536px; `max-md:`-style prefixes become `max-width`) and are mapped through the [breakpoint table](#media-queries--breakpoints) like any other query. Because KUBUILD breakpoints are coarser than Tailwind screens, `sm:` behaves like `md:` (tablet and desktop) and `xl:`/`2xl:` fold into `desktop`; these are reported as `CSS_MEDIA_APPROXIMATED`.
- **State prefixes** `hover:`, `focus:`, `active:`, `focus-visible:` and `disabled:` become pseudo-classes and land in `styles.states`.
- Rules are ordered by variant and then by an approximation of Tailwind's utility order, so combinations such as `p-6 px-4` or `border border-gray-300` resolve the way Tailwind would.

### Supported utilities

Spacing (`p*`, `m*`, negative margins, `gap*`, `space-x/y`), sizing (`w`, `h`, `size`, `min/max-w/h`, fractions, `screen`), layout (`display`, `position`, inset, `z`, `overflow`, `container`, `order`), flexbox (direction, wrap, `flex-1`, grow/shrink, basis, `items`, `justify`, `self`, `content`, `place-*`), grid (`grid-cols/rows-N`, `col/row-span`, `col-start`, `grid-flow`), typography (sizes with their paired line-heights, weights, families, alignment, color, `leading`, `tracking`, transform, decoration, `italic`, whitespace, `truncate`), colors (the full v3 palette with 50–950 shades, `white`/`black`/`transparent`/`current`, `/NN` opacity), backgrounds (color, gradients via `bg-gradient-to-*` with `from`/`via`/`to`, size/position/repeat), borders (width, per-side width, style, color), radius, shadows, opacity, transitions/duration/ease, and simple `scale`/`translate`/`rotate`.

Arbitrary values (`p-[13px]`, `bg-[#123456]`) are accepted only from a strict character allowlist and must fit the property type. Every generated declaration passes the same safety check as stylesheet CSS; a class with an unsafe value is dropped and reported.

### Not mapped

| Class | Reason reported |
| :--- | :--- |
| `group-*`, `peer-*`, `dark:`, `before:`/`after:`, `first:`/`last:` | `unsupported variant` |
| Stacked responsive + state variants (`md:hover:underline`) | `responsive and state variants cannot be combined` (the style format has no per-breakpoint states) |
| `ring-*`, `divide-*`, filters and `backdrop-*`, `animate-*`, plugin utilities | `unknown utility or unsupported value` |
| Arbitrary properties (`[mask-type:luminance]`) | `arbitrary properties are not supported` |

Each unmapped class is reported **once per import** as `CSS_UNSUPPORTED_SELECTOR` (severity `info`) with `location.selector = ".<class>"` and `details: { source: 'tailwind', className, reason }`; filter on `details.source` to tell them apart from regular selector diagnostics. Transforms are not composed either: `scale-105` and `-translate-y-1` on the same element override each other. The full rationale, including why the `tailwindcss` package is not used, is in the decision record `docs/adr-002-tailwind-utility-classes.md` in the repository.

## Overriding Computed Styles

`styleOverride` lets a host replace the statically computed cascade of individual elements with styles it measured some other way (the editor's [browser-snapshot mode](#browser-snapshot-styles) is built on it). The importer itself stays DOM-free: it computes the static result first and then routes it through the hook.

```ts
type HtmlStyleOverride = (
  element: DefaultTreeAdapterMap['element'], // sanitized parse5 element
  computed: ComputedElementStyles, // the static result: { base, mediaQueries, pseudoStates }
) => ComputedElementStyles | null | undefined;
```

- The hook is called synchronously for every element the rules convert (including `<body>`, a sole `<main>` and fallback embeds), in every entry point.
- Return a full `ComputedElementStyles` to replace the static result. `mediaQueries` entries are CSS query strings and go through the same [breakpoint mapping](#media-queries--breakpoints); `pseudoStates` keys are selectors such as `':hover'`.
- Return `null` or `undefined` to keep the static styles. A hook that **throws** also falls back to the static styles for that element, silently, so a broken provider never fails the import.
- Match elements with `getElementPath(element)`, which returns a deterministic structural path such as `html:0/body:1/section:0/h1:0` (tag name plus index among the parent's element children). Two parses of the same input with the same options give the same paths, so measurements taken on the sanitized tree line up with the elements the hook receives. Also compare the tag name to guard against mismatches.

## Limitations

- **No JavaScript.** `<script>` is removed, inline handlers are stripped, and nothing is executed. Content rendered by JavaScript (SPAs, client-side templates, lazy-loaded sections) will be missing; import the server-rendered or exported HTML instead.
- **One page per import.** A `.zip` provides one entry HTML file plus its CSS and assets; links to other pages stay plain links.
- **Static cascade.** Styles are resolved without layout, so anything that depends on viewport measurement, `calc()` against the real viewport, or JavaScript-toggled classes is approximated. In the editor, [browser-snapshot styles](#browser-snapshot-styles) can measure the computed values instead.
- **Form actions are not wired.** `<form action>` is kept as a prop and reported; connect real submission through your host (`onFormSubmit`) or action pipelines.
- **Node budget.** Imports stop at `limits.maxNodeCount` (default 1000 nodes) with `LIMIT_EXCEEDED`; raise it for large pages.

## Security

| Removed | Diagnostic |
| :--- | :--- |
| `script`, `noscript`, `object`, `embed`, `applet`, `base`, `template`, `frame`, `frameset`, SVG `script`/`foreignObject`/`animate`/`set` | `ELEMENT_DROPPED` |
| `<meta http-equiv>`, `<link rel="import">`, and `<link>` with any rel other than stylesheet, icon or preload/prefetch/preconnect | `ELEMENT_DROPPED` |
| `on*` event handler attributes, `srcdoc`, `formaction` | `URL_BLOCKED` |
| `href`, `src`, `action`, `poster`, `srcset`, `xlink:href`, … with a scheme outside `limits.allowedUrlSchemes` (`javascript:`, `data:text/html`, …). `data:image/*` is allowed. | `URL_BLOCKED` |
| Inline `style` attributes with dangerous expressions | `URL_BLOCKED` |
| Asset URLs with executable extensions (`.exe`, `.js`, `.sh`, …) | `URL_BLOCKED` |

The `html-embed` fallback only receives markup that went through the same sanitizer, and iframes are only embedded when their `src` is a safe URL. The finished document is then validated by `validateDocumentSecurity`, so an import cannot produce a page that the editor or renderer would reject.

## Assets and Fonts

- Relative URLs are resolved against `baseUrl`. Without `baseUrl` they stay relative.
- With `assetResolver`, every image (`src`, `srcset`, `poster`, CSS `url(...)`) and video is passed through it. Returning an `AssetReference` (`{ type: 'asset', assetId, fallbackUrl, … }`) stores a portable asset reference that `exportStoraPackage` can package; returning a string replaces the URL. A resolver that throws or returns `null` keeps the resolved URL and adds an `ASSET_UNRESOLVED` info diagnostic.
- Fonts from Google Fonts / Bunny Fonts links and `@font-face` rules are added to `theme.fonts` (`"Open Sans"` → `theme.fonts["open-sans"]`). `@font-face` files are passed to `assetResolver` with `type: 'font'` so you can copy them, but the stylesheet itself is not rewritten.

See [Assets & AssetProvider](/docs/guides/assets) for how the editor and renderer resolve stored asset references.

## Importing a .zip Site

`importHtmlZip` accepts an archive of an exported static site. It picks the entry HTML file (`entryHtmlPath`, else a root `index.html`, else a single nested `index.html`, else the only `.html` file), reads linked stylesheets from the archive, and resolves relative media against the archive. Before unpacking anything it rejects:

- archives larger than `limits.maxDocumentSizeBytes` (default 5 MB, for the whole archive),
- zip-slip paths (`../`, absolute paths),
- zip bombs (`limits.maxZipExpansionRatio`),
- executable files (`limits.prohibitedAssetExtensions`).

All of these fail with `LIMIT_EXCEEDED`; a missing or ambiguous entry file fails with `ASSET_UNRESOLVED`.

Asset references that resolve inside the archive reach your `assetResolver` as the archive path (for example `site/img/hero.png`); without a resolver they stay as that path. `archiveAssets` returns the bytes of every non-HTML, non-CSS file so you can upload them:

## Custom Mapping Rules

A rule decides whether it handles an element (`match`) and what it becomes (`convert`):

```ts
interface HtmlMappingRule {
  id: string; // a host rule with the same id replaces the built-in rule
  priority: number; // higher runs first; built-in rules use 30–60
  match: (element, computed, context) => boolean;
  convert: (element, context, computed) => PageNode | PageNode[] | null;
}
```

- `element` is the sanitized `parse5` element (`tagName` is lower case, `attrs` is an array of `{ name, value }`). Use `getAttribute`, `hasAttribute` and `getTextContent` from the package to read it.
- `computed` holds the resolved cascade (`base`, `mediaQueries`, `pseudoStates`). Pass it to `buildResponsiveStyles(computed, context.report)` to get the same `ResponsiveStyles` the built-in rules produce.
- `context` provides `generateId(prefix)`, `convertChildren(element)` and `convertElement(element)` for recursion, the `report` for your own diagnostics, and the import `options`.
- Return a node, an array of nodes (for example the converted children, to unwrap an element), or `null` to drop the element silently.
- Rules are tried in priority order and the **first** match wins. A rule that throws is reported as `ELEMENT_DROPPED` and the element goes to the fallback.

<include meta='title="custom-rule.ts"'>../../../examples/html-import/custom-rule.ts</include>

A rule may only emit built-in component types or types listed in `allowedComponentTypes`. Any other type is dropped and reported as `ELEMENT_DROPPED`; it is replaced by an `html-embed` only when `fallback: 'embed'` is set explicitly. Register the custom component itself in your component registry so the editor and renderer can show it (see [Custom Components](/docs/guides/custom-components)).

Built-in rule IDs, for overriding:

| Priority | Rule IDs |
| :--- | :--- |
| 60 | `button-link` |
| 55 | `iframe-video`, `form-label` |
| 50 | `heading`, `paragraph`, `blockquote`, `code-block`, `divider`, `link`, `image`, `picture`, `video`, `form`, `input`, `textarea`, `select`, `button`, `list`, `list-item`, `table`, `table-row`, `table-cell`, `svg-icon` |
| 45 | `table-section` |
| 40 | `text`, `section` |
| 30 | `container` |

`createRuleRegistry()` and `DEFAULT_HTML_MAPPING_RULES` are exported too, for tooling that wants to inspect or test the effective rule set.

## Import Report

Every result carries a `report: HtmlImportReport`:

```ts
interface HtmlImportReport {
  diagnostics: Array<{
    code: HtmlImportDiagnosticCode;
    severity: 'error' | 'warning' | 'info';
    message: string;
    location?: { line?: number; column?: number; tagName?: string; selector?: string; path?: string };
    details?: Record<string, unknown>;
  }>;
  stats: {
    nodeCount: number; // nodes in the output
    fallbackCount: number; // ELEMENT_FALLBACK_EMBED count
    droppedCount: number; // ELEMENT_DROPPED count
    fidelityScore: number; // 0–100
    durationMs?: number;
  };
}
```

### Diagnostic codes

| Code | Typical severity | Meaning |
| :--- | :--- | :--- |
| `ELEMENT_DROPPED` | warning | An element was removed: prohibited for security, unsafe for an embed, a rule threw or emitted a disallowed type, or `fallback: 'drop'`. |
| `ELEMENT_FALLBACK_EMBED` | warning | No rule matched; the element was kept as a sanitized `html-embed`. |
| `CSS_UNSUPPORTED_SELECTOR` | info | A selector could not be matched (pseudo-elements, `:has()`, invalid syntax). Reported once per selector. Also used for [Tailwind classes](#not-mapped) the mapper could not translate, once per class, with `details.source = 'tailwind'`, `className` and `reason`. |
| `CSS_UNSUPPORTED_PROPERTY` | warning / info | `@import`, or a dangerous property such as `behavior` / `-moz-binding`, was dropped. Also used (with `details.source = 'tailwind'`) for a `tailwind.config` that is not a static object literal (warning) or has keys other than colors and fonts (info). |
| `CSS_MEDIA_APPROXIMATED` | info | A media query was mapped to breakpoints whose edges it does not match exactly, including Tailwind's `sm:` (640px) and `xl:`/`2xl:` screens. Reported once per query. |
| `ASSET_UNRESOLVED` | warning / info | An external stylesheet was not fetched, a resolver returned `null` or threw, or a `.zip` has no usable entry HTML (error). |
| `URL_BLOCKED` | warning | An unsafe URL, event handler, `srcdoc`/`formaction`, dangerous inline style, or executable asset was removed. Also used (severity `info`) for a `<form action>` the host must wire. |
| `DEPTH_FLATTENED` | warning | A branch deeper than `limits.maxTreeDepth` was flattened. |
| `LIMIT_EXCEEDED` | error | Input size, node count, or a `.zip` safety check failed, or the final document failed validation. |

### Fidelity score

`fidelityScore` estimates how much of the source survived as native, editable components:

```
native   = nodeCount − fallbackCount
score    = (native × 1 + fallbackCount × 0.5) / (native + fallbackCount + droppedCount) × 100
```

Embeds count half, dropped elements count zero. Because dropped elements include security removals, a page with many `<script>` tags scores lower even when it looks identical. Use the score as a hint for review, not as a pass/fail gate on its own:

### Browser snapshot styles

The static cascade cannot know what a browser would actually compute for complex layouts. As an opt-in, the editor can import with **browser-snapshot styles**: it rebuilds the sanitized HTML in hidden measurement iframes at one viewport width per breakpoint (by default 1280px desktop, 896px tablet, 375px mobile), reads `getComputedStyle` for a curated property set, keeps only values that differ from the browser's defaults (measured in an extra reference frame) and from breakpoint to breakpoint, and feeds the result back into `importHtml` through [`styleOverride`](#overriding-computed-styles). Mapping, normalization, assets and validation are identical to static mode.

In `HtmlImportModal` this is the **Browser snapshot styles** checkbox (preselect it with `defaultStyleMode="snapshot"`). In code, use `importHtmlWithBrowserSnapshot` from `@kubuild/editor` (also re-exported by `@kubuild/react`). It is browser-only and takes the normal import options plus optional `widths` (each must lie inside its breakpoint's range) and a per-frame `timeoutMs` (default 5000):

<include meta='title="browser-snapshot.ts"'>../../../examples/html-import/browser-snapshot.ts</include>

The lower-level pieces are exported too: `captureBrowserSnapshot(html, options)` returns the raw measurements keyed by [element path](#overriding-computed-styles), and `createSnapshotStyleOverride(snapshot)` turns them into a `styleOverride` hook.

**When the snapshot wins.** Only the measured properties take part: `display`, `position`, `zIndex`, flex and alignment properties, `gridAutoFlow`, color and `backgroundColor`, font family/size/weight/style, `lineHeight`, `letterSpacing`, text alignment/transform/decoration, `whiteSpace`, `opacity`, `boxShadow`, `objectFit`, `visibility`, min/max sizes, `listStyleType`, `verticalAlign`, and the `padding`, `border`, `borderRadius`, `gap` and `overflow` families. For each of them the static value is kept when the author wrote it as:

- a **relative or dynamic value** (`em`, `rem`, `%`, `vw`/`vh`, `calc()`, `clamp()`, `min()`/`max()`, `var()`, a unitless `line-height`), which a computed pixel value would freeze to one viewport, or
- a **shorthand the snapshot cannot reproduce** (`font`, `flex`, `flex-flow`, `background`, `place-*`, `grid`, `list-style`).

Otherwise the measured value replaces the static one in every layer. Everything outside the catalog (`width`, `height`, `margin`, grid tracks, background images, transforms, …) and all `:hover`/`:focus` states keep their static values, as do elements that are never recreated in the frame (`iframe`, `object`, `embed`, `template`, SVG `foreignObject`/animation elements, …).

<Callout type="warn" title="Tailwind pages: keep static mode">
  The measurement frames only contain the page's own `<style>`/linked CSS and `options.stylesheets`. The rules generated by the [Tailwind mapper](#tailwind-utility-classes) are not injected and the Tailwind CDN script never runs there, so for a page styled only by Tailwind classes the frames measure unstyled elements and can override mapped values. Use static mode for those pages.
</Callout>

**Fallback.** When measuring is impossible (no DOM, a frame cannot be created or times out, the parse fails), the import silently falls back to the static cascade: the result has `snapshotApplied: false` and the reason in `snapshotError`, and the dialog shows "Browser snapshot unavailable, static styles were used." The `.zip` upload in the dialog and [paste onto the canvas](#paste-html-onto-the-canvas) always use static mode for now.

**Security model.** The untrusted HTML is never handed to the browser's HTML parser:

- Each frame has `sandbox="allow-same-origin"` **only**. `allow-scripts` is never granted, so no `<script>`, `on*` handler or `javascript:` URL can run even if something slipped through; same-origin is what lets the editor read computed styles from outside. (A fully opaque `sandbox=""` frame would make computed styles unreadable; the full reasoning is in the header comment of `packages/editor/src/html-snapshot/frame.ts`.)
- The frame document is a fixed `srcdoc` shell whose first element is a CSP (`default-src 'none'; script-src 'none'; style-src 'unsafe-inline'; …`), so the frame cannot make any network request: no images, fonts, `@import`, frames or prefetches.
- The HTML is parsed and sanitized by `@kubuild/html-import` (`parseHtml` + `sanitizeAst`) and the resulting tree is rebuilt node by node with `createElementNS`/`setAttribute`/`createTextNode`, never `innerHTML`. Executable and network-capable tags are skipped, `on*` and URL-bearing attributes are dropped, links become `href="#"`, and `url()`, `@import`, `image-set()` and `src()` are neutralized in CSS text.
- Frames are off-screen, `inert`, `aria-hidden` and `pointer-events: none`, and are removed as soon as measuring finishes.
